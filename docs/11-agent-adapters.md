# 11 — Agent adapters

**Question this page answers:** how does one set of rules reach every IDE and CLI without duplicating maintenance?

**Canonical sources:**

| Source | Purpose |
|---|---|
| `AGENTS.md` | always-on rules and context map |
| `.agents/skills/*/SKILL.md` | on-demand procedures |
| `project/rules/*.md` | project-specific rules (lazy) |
| `project/` | living state and artifacts |

Everything else is **generated**. Never hand-edit an adapter file; edit the source and run:

```bash
./scripts/sync-adapters.sh
```

Generated files carry a `generated by` marker. The script overwrites files with the marker and refuses to touch files without it unless you pass `--force`.

---

## What gets generated

| Agent / IDE | Path | Strategy |
|---|---|---|
| OpenCode | `AGENTS.md`, `.opencode/skills/` | native + symlink |
| Claude Code | `CLAUDE.md`, `.claude/skills/` | symlink |
| Codex, Jules, Amp, Factory | `AGENTS.md` | native |
| Cursor | `.cursor/rules/*.mdc` | generated rules |
| GitHub Copilot | `.github/copilot-instructions.md` | generated copy |
| Gemini CLI | `GEMINI.md` | symlink |
| Windsurf | `.windsurf/rules/00-agents.md` | generated |
| Roo Code | `.roo/rules/00-agents.md` | generated |
| Zed | `.rules` | symlink |
| Aider | `.aider.conf.yml` | generated |
| JetBrains Junie | `.junie/guidelines.md` | generated |

The adapter list lives in `framework.conf` (`ADAPTERS`). Remove a name to stop generating it.

## How the sync works

```bash
./scripts/sync-adapters.sh            # link where possible, copy otherwise
./scripts/sync-adapters.sh --copy     # force copies (Windows, no symlinks)
./scripts/sync-adapters.sh --force    # overwrite non-generated files
```

Behavior:

- **Symlinks** are used for files that are identical to the source (`CLAUDE.md`, `GEMINI.md`, `.rules`, skill directories). They stay in sync automatically.
- **Copies** are used where the target format needs frontmatter or a different filename (Cursor, Copilot, Windsurf, Roo, Aider, Junie).
- Existing user files are preserved. The script prints a warning and skips them.
- A generated file starts with `<!-- generated by agent-project-framework -->`; that marker authorizes overwrite.

### Cursor

Cursor rules use `.mdc` frontmatter. The sync generates:

- `000-agents.mdc` — `alwaysApply: true`, the full `AGENTS.md`.
- `100-skill-<name>.mdc` — `alwaysApply: false`, `description` from the skill, body included for on-demand activation.

If your Cursor version prefers "Agent Requested" rules, the description is the trigger. Keep descriptions specific: "Use when writing or changing product code", not "Helps with code".

### Copilot

`.github/copilot-instructions.md` is always loaded by Copilot. It receives the full `AGENTS.md` plus a short note pointing to skills. Keep `AGENTS.md` lean or Copilot pays the full cost every request.

### Gemini CLI

Gemini CLI reads `GEMINI.md` by default and can be configured to read `AGENTS.md`:

```json
// .gemini/settings.json
{ "context": { "fileName": "AGENTS.md" } }
```

The sync creates `GEMINI.md` as a symlink for compatibility.

### Aider

`.aider.conf.yml`:

```yaml
read:
  - AGENTS.md
```

Aider also reads `CONVENTIONS.md` if configured; do not duplicate the rules there.

### Windsurf / Roo

Both read a directory of markdown rules. The sync generates one always-on file from `AGENTS.md`. If the tool supports scoped rules, add `project/rules/` files as separate generated rules only when they are small and always relevant.

### Junie

`.junie/guidelines.md` receives the full `AGENTS.md`. JetBrains users can keep the file open while the agent works.

## Windows notes

Symlinks require Developer Mode or an elevated shell. If symlink creation fails:

```powershell
./scripts/sync-adapters.sh --copy
```

With `--copy`, re-run the sync after changing any rule or skill. Add it to your pre-commit checklist or a file watcher.

Git may check out symlinks as plain text on Windows. Set:

```bash
git config core.symlinks true
```

If that is not possible, use `--copy` and commit the generated copies.

## Monorepos

- Root `AGENTS.md` holds global rules and the context map.
- Each package may have its own `AGENTS.md` with package-specific commands and invariants. The closest file wins.
- Keep package `AGENTS.md` under 40 lines; link to the root for everything else.
- Skills remain at the root; package-specific skills can live in `.agents/skills/` with a clear prefix (`billing-...`).
- Regenerate adapters from the root after any change.

Example:

```
/AGENTS.md
/packages/api/AGENTS.md
/packages/web/AGENTS.md
/.agents/skills/
```

## Verifying an adapter

1. Open the tool in the project root.
2. Ask: "What is the current project phase and next action?"
3. Expected answer: it reads `project/STATE.md` and names the phase + next action.
4. Ask: "Which skill would you use to split a large task?"
5. Expected answer: `plan-and-slice`, without reading the whole repo.

If the agent does not see the rules:

- Confirm the adapter file exists and is not empty.
- Check the tool's docs for the exact filename and precedence.
- Restart the tool or start a new session; some tools cache instructions.
- For symlinks, confirm the target resolves (`ls -l CLAUDE.md`).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Agent ignores `AGENTS.md` | wrong file for the tool | check the table above |
| Rules duplicated or stale | hand-edited adapter | edit source, re-run sync |
| Skill not triggering | weak description | rewrite with "Use when..." and concrete triggers |
| Agent reads the whole repo | no context map or weak instruction | reinforce §3 and §9 |
| Copilot slow/expensive | `AGENTS.md` too large | run `token-audit.sh`, trim |
| Symlink broken after clone | Windows checkout | use `--copy` |
| Cursor rule never loads | `alwaysApply: false` and no match | improve description or set `alwaysApply: true` for core only |

## Adding a new adapter

1. Add the tool name to `ADAPTERS` in `framework.conf`.
2. Add a branch in `scripts/sync-adapters.sh`.
3. Document the path and format in this file.
4. Run `./scripts/sync-adapters.sh` and verify.
5. Keep the generated output small; prefer a pointer to `AGENTS.md` when the tool supports it.
